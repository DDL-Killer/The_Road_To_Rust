# 编程语言相关概念

## 概念1

1. 静态类型语言:所有数据都类型在编译时已知
2. 动态类型语言:在运行时才知道数据的类型
3. 强类型语言:对数据类型的赋值进行规则约束
4. 弱类型语言:对数据类型的赋值约束少/无约束

| 特性       | 静态类型     | 动态类型     |
| ---------- | ------------ | ------------ |
| 类型检查   | 在编译时     | 在运行时     |
| 错误检测   | 早(在执行前) | 晚(执行期间) |
| 代码灵活性 | 低           | 高           |
| 性能       | 通常更快     | 可能会更慢   |
| 示例       | Rust,Java++  | Python       |


| 特性         | 强类型              | 弱类型                      |
| ------------ | ------------------- | --------------------------- |
| 数据类型声明 | 显式、隐式          | 隐式                        |
| 类型约束     | 严格                | 宽松                        |
| 类型转换     | 需要显式进行        | 隐式进行                    |
| 隐式转换     | 少见/罕见           | 常见                        |
| 错误检查     | 多在编译时          | 多在运行时                  |
| 类型安全性   | 高;较少出现意外行为 | 低;更容易出现不可预期的结果 |
| 示例         | Rust,Java           | JavaScript                  |

## 概念2

### 编译型语言

用户看不见源代码

### 解释型语言

用户能看见源代码,需要安装解释器来执行,实时进行解释



| 特性       | 编译型语言                         | 解释型语言                             |
| ---------- | ---------------------------------- | -------------------------------------- |
| 编译过程   | 需要编译步骤来生成可执行文件       | 无需编译,代码直接由解释器执行          |
| 编译时间   | 编译大型项目可能耗时较多           | 及时反馈,无需编译                      |
| 依赖性     | 只需要二进制文件和必要的库即可执行 | 需要安装解释器才能执行代码             |
| 可移植性   | 需要为不同平台重新编译             | 任何有解释器的平台都可以执行           |
| 执行速度   | 通常更快                           | 通常较慢                               |
| 内存使用   | 通常更节省内存,编译时会进行优化    | 由于解释开销,可能会占用更多内存        |
| 修改和测试 | 修改后需要重新编译,迭代较慢        | 修改后可直接测试,无需重新编译,迭代较快 |
| 示例       | C,C++,Rust                         | Python,JavaScript                      |
